011994. An SGI Indy sits on a desk.

01On the screen, a frame appears: a grid of coloured pixels.

01The frame lives in one machine, in one framebuffer, inside one operating system.

01If the machine stops, the frame stops with it.

01That was the deal: one computer, one box.

02A regular operating system is built around one machine.

02One kernel owns the processor, the memory, the devices and the processes.

02To use a second machine, you add a second kernel.

02Then you build a distributed system above both: a network file system, a message queue, a cluster.

02The frame can cross the border, but it needs a new layer to carry it.

02Every layer brings its own idea of identity, naming and failure.

03IRIX 7 starts with a different unit: the logical computer.

03One node is a complete computer.

03A hundred and twenty-eight nodes are still one computer.

03Every node runs the same core; a native shim owns its hardware.

03The frame becomes an object in a global space.

03Objects, actors and devices share one set of names.

04The frame is an object.

04Its name is computed from its contents: a BLAKE3 hash over kind, length and bytes.

04An immutable object can be copied, cached and verified by anyone.

04A mutable object keeps a stable identity, and one home owns its current root.

04A file, a directory, a device, an actor: each is an object with a name.

04The frame has a name now. The system can find it anywhere.

05A path gives the frame a location. Permission is a separate question.

05IRIX 7 answers it with a capability: a signed token that names the object, the holder and the rights.

05The token carries the frame's home, its epoch, an expiry and a signature.

05You can pass on a weaker copy of your capability.

05Revocation moves the object's epoch, and the old tokens stop working.

05Authority is explicit, signed, and small enough to carry in a message.

06Every object has a home: one node that owns its current state.

06The home is chosen by rendezvous hashing over the nodes in the membership.

06Every node computes the same table from the same snapshot.

06A node's shard is the set of objects whose home it is.

06When an object moves, the old lease ends, the epoch advances, and the next request retries at the new home.

06The table is the directory. Every node keeps its own copy.

07A program asks for the frame. The frame may be on this node, or on another one.

07Both calls use the same invocation model.

07A local call stays inside the node. A remote call carries a header: source, destination, home, route and epoch.

07The fabric carries tags, streams, deadlines, dependencies and trace context.

07A GPU on another node is still an object: submit a command buffer, receive the result.

07The frame comes back, and appears on the screen.

08Now unplug the home node.

08The membership changes. The epoch advances. The old lease is fenced.

08The frame moves to a new home.

08A partition can make the frame unavailable. The epoch keeps one home authoritative.

08The screen freezes for a moment, then resumes.

08Failure is a state the system knows how to handle.

09The frame was drawn by a program written for IRIX 6.5.

09IRIX 7 keeps POSIX and the IRIX ABI native.

09The new core sits beside them, managing policy, namespace and placement.

09A C probe boots. The o32 loader runs open, read, write, close and exit.

09An actual IRIX binary, TLS and the full container are still ahead.

09The old program and the new system meet at the frame.

10The first target is the machine on the desk: a 1994 SGI Indy.

10A MIPS R4400, 256 megabytes, Newport graphics, Seeq Ethernet, WD33C93 SCSI.

10An assembly ROM sizes the memory, tests every byte, brings up serial, decompresses the kernel and jumps.

10The kernel brings up the network, the boot log, the telnet console and module loading.

10v0.1.3 boots on iris. Real Indy hardware is the next step.

10The frame returns to the screen where it started.

11In November 2026, one node works on iris.

11Two nodes work on two real kernels: join, placement, routing, migration and failure fencing.

11Eight nodes are in progress; the first slice runs on two real kernels.

11A hundred and twenty-eight nodes are planned.

11Each number has evidence behind it.

11The work continues from here.

12The frame is still on the Indy.

12The same object is on every node that needs it.

12The computer is the network.
