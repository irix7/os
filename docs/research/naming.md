# Naming study: keeping the IRIX sound after IRIX 7

Status: **research note and recommendation**. 2026-10-25. This is not an ADR.

## Recommendation

The priority is now clear: **IRIX is the name you actually want**. The honest
answer is that IRIX itself is not realistically registrable, but the sound of it
is. There are three good tracks, plus a literal long-form fallback.

### Track A — keep the IRIX sound: `Jovrix`

**Adopt `Jovrix`** (JOV-riks) if the IRIX identity matters most.

`Jovrix` is **Jove + IRIX**: the Jupiter root with the `-rix` cadence of IRIX. It
is the closest a new name can get to IRIX while still being a different mark. It
is short, hard, and reads as a Unix:

```
$ uname -a
Jovrix 1.0 indy MIPS-III
$ echo $HOSTNAME
indy
```

> **Jovrix — Jupiter's IRIX for the Indy.**

The US federal screen found **no `JOVRIX` marks**. npm, PyPI and crates.io are
free; `github.com/jovrix` is available; `jovrix.io`, `.dev` and `.net` had no DNS
record; `jovrix.com` is listed for sale. The name is used by a handful of social
media and music accounts, not by a software company or an OS.

The one serious caution is **`JOVIX`**, a live class 9 software mark (construction
material tracking, now part of Hexagon). `Jovrix` is one letter away. That is the
single biggest legal risk in this report and the reason a formal clearance search
is mandatory. If Jovix is a problem, Track B or Track C is the fallback.

### Track B — keep Indy + IRIX: `Indrix`

**Adopt `Indrix`** (IN-driks) if the machine matters as much as the OS.

`Indrix` is **Indy + IRIX**: it compresses the machine and the operating system
into one word, and it sounds like the missing model between `Indigo` and `IRIX`.

> **Indrix — the Indy's IRIX.**

The US screen found **no `INDRIX` marks**. npm, PyPI and crates.io are free;
`indrix.io` had no DNS record; `indrix.com` is for sale. The caution is that
`INDRIX` is already the name of a European civil-protection data tool by
Samaritan International, and `github.com/indrix` / `github.com/indrix-dev` are
taken. That is a common-law software risk, not a registered mark, but it is real.

### Track C — clean break: `Jovis`

**Adopt `Jovis`** (JOH-vis) if you want a name with no IRIX baggage at all.

`Jovis` is the genitive of the Latin *Iuppiter*: it means **"of Jupiter"**. It is
the most elegant Jupiter name, and it is clean in the US register (only two dead
`JOVIS` marks). But it does not preserve the IRIX sound. It is the right choice
only if the IRIX resemblance matters less than the Jupiter identity.

> **Jovis — of Jupiter. A Unix for the Indy.**

### The four-track summary

| Track | Name | Construction | Why choose it | Main risk |
|---|---|---|---|---|
| A | **Jovrix** | Jove + IRIX | closest to IRIX, Jupiter root, short | one letter from live `JOVIX` |
| B | **Indrix** | Indy + IRIX | closest to the Indy/IRIX lineage | existing `INDRIX` software |
| C | **Jovis** | genitive of Jupiter | cleanest Jupiter name, no IRIX baggage | less IRIX-like |
| D | **Jupitrix** | Jupiter + IRIX | most literal Jupiter + IRIX; no US marks | long, less punchy |

`Jupitrix` (JOO-pi-triks) is the literal long form: **Jupiter + IRIX**, no US
marks, clean packages, `jupitrix.com` registered but `github.com/jupitrix`
available. It is a useful fallback if `Jovrix` fails the Jovix test but you still
want both roots.

### Track E — the seven track: `Septimux` (or `Septimix`)

**Adopt `Septimux`** (SEP-ti-muks) if the "7" is the real attachment — or, better,
**`Septimix`** (SEP-ti-miks), the same idea with the `-ix` ending of IRIX/Unix
instead of the `-mux` of a multiplexer.

`Septimux` is **Septimus + Unix**: Latin *septimus* ("seventh") with the `-ux` of
Unix. It is the seventh Unix for the Indy, and it sounds like one.

> **Septimux — the seventh Unix for the Indy.**

The US screen found **no `SEPTIMUX` marks**; npm, PyPI and crates.io are free;
`github.com/septimux` is available; `septimux.net`, `.org` and `.io` were
available, and `septimux.com` is registered but listed for sale. It is cleaner
than `Seven OS` and more distinctive than `Septimus`.

The catch is the `-mux`: it reads as "multiplexer" (`tmux`, `screen`, `mux`), so
some people will hear a terminal tool rather than an OS. `Septimix` removes that
problem: it keeps the 7 and the Unix `-ix`, and `septimix.com` is available. See
the variants below.

### The five-track summary

| Track | Name | Construction | Why choose it | Main risk |
|---|---|---|---|---|
| A | **Jovrix** | Jove + IRIX | closest to IRIX, Jupiter root, short | one letter from live `JOVIX` |
| B | **Indrix** | Indy + IRIX | closest to the Indy/IRIX lineage | existing `INDRIX` software |
| C | **Jovis** | genitive of Jupiter | cleanest Jupiter name, no IRIX baggage | less IRIX-like |
| D | **Jupitrix** | Jupiter + IRIX | most literal Jupiter + IRIX; no US marks | long, less punchy |
| E | **Septimix** | Septimus + `-ix` | keeps the 7, IRIX/Unix `-ix`, clean screen | no Indy/Jupiter; `-mux` variant reads as a tool |

**My pick depends on the anchor.** If the SGI/IRIX identity is the anchor,
`Jovrix`; if the 7 is the anchor, `Septimix` (the cleaner `-ix` form of
`Septimux`); if the machine is the anchor, `Indrix`; if you want a clean break,
`Jovis`. `Jupitrix` is the literal fallback if `Jovrix` fails the Jovix test but
you still want both roots.

## Can we just trademark IRIX?

No. The name is not available as a registered mark for an operating system, and
using it unregistered would be worse.

The US federal screen returns **20 `IRIX` marks**. The live ones include:

| Mark | Owner | Class | Goods |
|---|---|---|---|
| `IRIX` | Milliman, Inc. | 42 | SaaS that interprets insurance applications |
| `IRIX` | Xtant Medical Holdings | 10 | Orthopaedic fixation devices |
| `IRIX` | Xaar plc | 7, 9 | Inkjet printing machines and apparatus |
| `IRIX` | DWS SRL | 1 | Resins for 3D printers |
| `IRIX` | Tao Duan (pending) | 28 | Amusement machines |

The original Silicon Graphics `IRIX` application for operating-system software
(serial 74484101, class 9) is **dead/abandoned since 1995**. That does not make
the name free:

- **Milliman's live class 42 mark** is in the software/SaaS neighbourhood, which
  is exactly where an OS would be filed. A US application for `IRIX` in class 9
  or 42 could face a Section 2(d) refusal citing it.
- **HPE** acquired SGI in 2016 and its support site still carries IRIX 6.5.30
  patches. The name retains SGI/HPE goodwill, even without the old class 9
  application.
- **Irix Lens** uses `IRIX` commercially in optics.
- **`irix7.com`** is already a third-party "IRIX 7.0" technical archive.
- **`IRYX OS`** is a live/pending class 9 mark for an operating system, filed in
  2026. The obvious "IRIX with a Y" is already taken. The IRIX-adjacent space is
  being mined.

So the choice is not "IRIX or a new name". It is "an IRIX-adjacent name we can
own, or an unregistrable IRIX that we will have to defend". Track A or B is the
answer if the IRIX identity is the priority.

**Could we use `IRIX` anyway, without registering it?** You can use it
descriptively — "runs IRIX 6.5 application binaries" — because that is a factual
statement about compatibility. You cannot use it as the product name, logo,
domain or release brand without risking a claim from Milliman, HPE or Irix Lens.
A small non-commercial project might stay under the radar, but the name would
still be unregistrable, would collide with `irix7.com`, and would cap the
project's ability to grow. That is the trade the new name is buying you out of.

**Could a licence or coexistence agreement solve it?** Theoretically: Milliman
could consent, and HPE could license the name. In practice, that is a commercial
negotiation with large companies for a name that is not core to either of them,
and it would still leave the `irix7.com` and Irix Lens confusion. It is not a
good use of the project's early capital.

while remaining distinct marks.

## Seven OS

The appeal is obvious: `Seven` is short, clean, and keeps the "7" from IRIX 7
without using the IRIX mark. It also has a Unix precedent — Plan 9, Inferno,
Haiku, Redox, SerenityOS — a number or a single word can be a Unix name. But the
screen is not kind:

- **It is already an OS name.** `Dzy0726/SevenOS` is an operating-system course
  project from Tongji University (2020), built on Orange's OS. `kimwlsgh33/SevenOS`
  and `kiperos/sevenos` are also on GitHub, and `Coder2058/SevenOS` is a DOS
  emulator. `MhlongoRRB/SeventhOS` is a Windows 7 interface recreation.
- **The namespace is messy.** `sevenos.com` is Seven O's RV, a business in
  Kirkville, New York; `sevenos.org` is registered; `github.com/sevenos` and
  `github.com/seven-os` are taken. `sevenos.net`, `sevenos.io` and `seven-os.com`
  are available, and npm/PyPI/crates are free, but the `.com` and GitHub names are
  not.
- **`Seven` is a very crowded brand.** The broad US search returns thousands of
  marks, and the class 9 and class 42 counts alone are in the thousands. In
  Australia, "Seven" is the Channel 7 / Seven West Media brand. A number is a weak
  mark: it is hard to protect, hard to search, and easy to confuse with Windows 7,
  Android 7 and every "7" product.
- **It drops both SGI and Jupiter.** The only thing it keeps is the number 7 —
  and IRIX 7 never existed. That is a thin story for a new identity.

**Verdict: not recommended.** If the "7" is the appeal, `Septimux` is the name
to beat: it keeps the seven, sounds like a Unix, and is clean in the US register
and package registries. `Septimus` is the quieter Latin alternative. Both still
do not carry Indy or Jupiter.

## Septimux

`Septimux` is the name `Seven OS` should have been. It is **Septimus + Unix**:
the Latin ordinal for "seventh" with the `-ux` ending that reads as Unix. It
keeps the 7, it sounds like a Unix, and it is clean.

- **US marks:** no `SEPTIMUX` marks (Trademarkia, 25 October 2026).
- **Packages:** npm, PyPI and crates.io all returned 404.
- **Domains:** `septimux.com` is registered and listed for sale; `septimux.net`,
  `septimux.org` and `septimux.io` had no RDAP record; `septimux.dev` and
  `septimux.au` had no DNS.
- **GitHub:** `github.com/septimux`, `septimux-os` and `septimuxos` were
  available.
- **Existing use:** no exact matches surfaced in the web search; the name is
  effectively unclaimed.
- **The `-mux` risk:** `mux` is a multiplexer (`tmux`, `screen`, `mux`), so the
  name can read as a terminal tool. This is the one stylistic objection.

### Septimux variants

The same construction yields two cleaner variants:

| Name | Construction | US marks | Packages | `.com` | GitHub | Verdict |
|---|---|---|---|---|---|---|
| **Septimix** | Septimus + `-ix` | none | free | available | available | **best seven name** |
| **Septirix** | Septimus + `-rix` | none | free | available | available | closest to IRIX; `-rix` risk |
| **Septimux** | Septimus + `-ux` | none | free | for sale | available | `-mux` reads as multiplexer |
| **Septrix** | seven + `-rix` | not checked | free | taken | taken | possible |

`Septimix` is the pick of the three: it keeps the 7, has the `-ix` ending that
reads as Unix/IRIX, and is clean on every registry, domain and GitHub check. It
is the seven name I would actually use. `Septirix` is the closest to IRIX, but
the `-rix` may be too close to the live `IRIX` mark, so it needs the formal
search more than `Septimix` does.

**Verdict:** `Septimix` is the best "seven" name in the study and a serious
Track E. It does not carry Indy or Jupiter, but it carries the 7 and the Unix
identity better than `Seven OS`, `Septimus` or `Septima`. If the 7 is what you
actually want to keep, this is the pick.

## Why "IRIX 7" is a liability

The trademark problem is set out above. Three further problems compound it.

### `irix7.com` is already someone else's site

`https://irix7.com/` is **"IRIX 7.0 — Silicon Graphics Technical Document
Archive"**, maintained by Kevin Stoiber and last updated 3 March 2026. The
project's documentation is at `irix7.github.io/os`; the `.com` is a third party.
That is a direct namespace collision, not a hypothetical one. It also means
search results for "IRIX 7" will mix the project with an established archive.

### "IRIX 7" never existed

IRIX's final release was **6.5.30 on 16 August 2006**; support ended in December
2013. "IRIX 7" is associated with a **rumoured late-1990s port of IRIX to
Itanium** that never shipped. Naming a new OS "IRIX 7" implies an official
version that never was, blurs the clean-room story, and invites the question
"which IRIX 7?" The project is a successor *in spirit* to IRIX 6.5, not a
recovered SGI release.

### The rename gets more expensive every week

The repository currently returns roughly **1,300 `IRIX 7` matches and 1,250
`irix7` matches across 188 files**. That is the raw grep count, including
generated documentation and binary artefacts; the source-only count is smaller,
but the direction is clear: the module SDK, boot config URLs, release artefacts
and documentation all encode the old name. Renaming before v1.0 is a mechanical
change; renaming after the module ecosystem and ABI are public is a migration.

The compatibility claim **"runs IRIX 6.5 application binaries unchanged"** is
nominative fair use and should stay as a factual statement. The OS name should
not be IRIX.

## Criteria

A good name here has to satisfy seven things at once:

1. **In the realm.** It should feel at home on a 1993 SGI desk and in the
   Jupiter system: one word, technical or classical, not a generic English noun.
2. **Sounds like a Unix.** Short, ideally two or three syllables, with a hard
   consonant and a classical ending (`-is`, `-us`, `-ix`, `-rix`, `-ans`). It
   must look right in a prompt (`jovrix$` or `jovis$`), in `uname`, as a package
   prefix (`jovrix-libc` or `jovis-libc`), and in a URL.
3. **Distinctive.** No existing OS, no live class 9/42 trademark, no major
   software brand. A small hobby project with the same name is tolerable; a
   shipping operating system is not.
4. **Practical.** Easy to spell after hearing it, no ambiguous pronunciation,
   available package names and a workable domain and GitHub namespace.
5. **SGI-shaped.** SGI's best names are one word with a hard edge: `Onyx`,
   `Octane`, `Origin`, `Fuel`, `Tezro`, `Indy`, `Indigo`. The name should sound
   like it belongs in that list without borrowing one of its entries.
6. **Personal.** It should honour Jupiter without being the literal word
   `Jupiter`, which is generic, crowded, and already the user's own name.
7. **IRIX-adjacent, if that is the priority.** If the name is meant to carry the
   IRIX identity, it should share the `-rix` cadence or the `Ind-`/`Iri-` root
   without being IRIX. A pure Jupiter name is the alternative, not the
   requirement.

## The two naming worlds

### SGI's names and codenames

SGI's product names and internal codenames are a useful style guide. The
primary source is the *Hardware Developer Handbook 2.0* (Tables 1-1 to 1-3 and
the glossary), which maps each marketing name to its chassis, CPU and graphics
codename.

| Marketing name | Codename | What it was |
|---|---|---|
| Indy | Guinness | Low-end desktop, 1993 |
| Indigo | Hollywood | Desktop |
| Indigo2 | Fullhouse | Desktop |
| O2 | Moosehead | Desktop |
| Octane | Speedracer | Desktop |
| Origin 200 | Speedo | Deskside server |
| Origin 2000 / Onyx2 | Lego | Deskside/rack |
| Onyx / Challenge | Eveready / Terminator | Deskside/rack |
| Crimson | Diehard2 | Deskside |
| Personal IRIS | Eclipse / Magnum | Deskside |

The CPU and graphics projects had their own names: `Lonestar` (R4000),
`Twin Peaks` (R8000), `Triton` (R5000), `T5` (R10000); `Clover`, `Stapuft`,
`Venice`, `Da Vinci`, `Express`, `Ultra`, `Newport`, `Mardi Gras`, `Kona`.
IRIX 4.0 was `Cypress`; the 3000 product was `Juniper`.

The patterns are clear:

- **One word, hard consonants, two or three syllables.**
- **Colours and minerals:** Onyx, Crimson, Indigo.
- **Abstractions:** Origin, Challenge, Fuel.
- **Beer and pop culture:** Guinness, Moosehead, Speedracer, Terminator, Lego.
- **Classical and technical:** Triton, Juniper, Kona.

The OS name should use the classical/technical register, not the beer register.
It should also not be an SGI product name: `Indy`, `Indigo`, `Iris`, `Onyx`,
`Octane`, `Origin`, `Fuel`, `Tezro`, `Altix`, `Virtu`, `Prism`, `Crimson` and
`Challenge` are either live or abandoned SGI marks, or generic words with heavy
existing use. Reusing one would recreate the IRIX problem.

### Jupiter's names

Jupiter gives us four families:

- **The god's names.** *Iuppiter* (nominative), **Iovis** (genitive, "of
  Jupiter"), *Jove* (English), *Jovius* / *Jovian* (adjectives). The god's
  epithets include **Tonans** ("Thunderer"), **Fulmen** (the thunderbolt),
  **Elicius** (who elicits lightning), **Summanus** (nocturnal thunder) and
  **Veiovis** (a young/underworld aspect).
- **His symbols.** The eagle **Aquila**, the oak **Robur** or **Ilex**, the
  thunderbolt, the sceptre.
- **His family.** Juno (wife), Minerva (daughter, wisdom), Juventas (daughter,
  youth), Bellona (daughter, war), and the many nymphs and mortals he loved.
- **His moons.** Io, Europa, Ganymede, Callisto; then Amalthea, Thebe,
  Adrastea, Metis, Leda, Elara, Himalia, Carme, Ananke, and the rest. The inner
  ring moons are Metis, Adrastea, Thebe and Amalthea.

The pure Jupiter intersection is **Jovis**: the god's own genitive, the planet's
Latin name, and a word that sounds like a Unix. The IRIX-adjacent intersection is
**Jovrix**: Jupiter's root with IRIX's cadence. The OS is *of Jupiter*; the
machine is *Indy*; the release names are *Jupiter's moons*.

## Screening

### Method

The screen combined:

- primary sources for SGI names (the *Hardware Developer Handbook 2.0*) and for
  the Latin (Wiktionary / Lewis & Short);
- web research on each candidate's existing software and OS use;
- package-registry checks on npm, PyPI and crates.io;
- DNS and RDAP checks for `.com`, `.net`, `.org`, `.dev`, `.io` and `.au`;
- GitHub namespace checks;
- a quick US federal trademark screen via Trademarkia.

The trademark screen is a **preliminary screen, not a clearance search**. It
covers US federal records only, and it does not replace advice from an Australian
or US trademark attorney.

### Also screened

These were considered and set aside for the reason given:

- **Juventas** (Jupiter's daughter, youth): rare and clean, but not Unix-shaped;
  "Juventus" confusion.
- **Bellona** (war): usable but aggressive, and a company/place name.
- **Summanus** (nocturnal thunder): good meaning; `Summanus Ltd` is a game-key
  wholesaler, and the asteroid/astronomy use is strong.
- **Elicius** and **Veiovis** (Jupiter epithets): clean and obscure, but too
  obscure for a first name; better as release codenames.
- **Aquila** (Jupiter's eagle): beautiful, but Aquila is a drone, a CMS and a
  constellation; crowded.
- **Ilex** (holm oak): clean-ish, but Ilex is an identity-management software
  company.
- **Adrastea** (nurse/moon): lovely, but an FPGA design environment, a Comet
  Backup release and a Würth cellular module all use it.
- **Elara**, **Himalia**, **Carme** (moons): usable, but either a company (Elara),
  a mountain-range confusion (Himalia), or a "karma" confusion (Carme).
- **Iridis** (Latin "of Iris", SGI's original name): sounds excellent and is
  close to the SGI lineage, but the University of Southampton supercomputer
  `Iridis` owns the computing association, and it is one step removed from
  Jupiter.
- **Indix** (Indy + IRIX): the best pure coinage for the old identity, but
  `Indix` is an existing product-intelligence company and the word reads as a
  typo for "index".
- **Jovium** and **Jovux**: clean in the registries, but `Jovium` is a
  BrandBucket domain and a wellness brand, and `Jovux` is one letter from the
  live `JOVIX` mark. Neither is worth the risk when `Jovis` is available.
- **Indigo, Onyx, Octane, Origin, Fuel, Altix, Virtu, Prism, Crimson,
  Challenge, O2**: SGI names, SGI marks, or generic words with heavy use.
- **Kona, Newport, Venice, Mardi Gras, Speedracer, Fullhouse, Hollywood,
  Guinness, Moosehead, Lego, Terminator, Predator, Diehard, Eveready**: SGI
  codenames that are beer brands, place names, films or toys. Good history, bad
  trademarks.
- **Seven OS**: see the Seven OS section above. It is already an OS project name,
  the `.com` is an RV company, and "Seven" is a crowded brand.
- **Septimux**: the better seven name; see the Septimux section. Clean US screen,
  clean packages, available GitHub; reads as "mux".

## The Track C shortlist

This is the pure-Jupiter shortlist behind Track C. The IRIX-adjacent shortlist
(`Jovrix`, `Indrix`, `Jupitrix`) is above.

### 1. Jovis — the clean break

**Meaning.** *Iovis* is the genitive of *Iuppiter*; `Jovis` is the same word with
the I/J spelling used in English and in later Latin. It means **"of Jupiter"**.
It appears in *Villa Jovis* ("Villa of Jupiter") on Capri, in the Eurorack module
*Muta Jovis*, and in the name of the JANUS camera on ESA's JUICE mission:
*Jovis, Amorum ac Natorum Undique Scrutator* ("of Jupiter, scrutiniser of
lovers and children everywhere").

**Sound.** Two syllables, first-syllable stress, a hard `v`, and the `-is` ending
of `IRIS` and `Solaris`. It is the most elegant pure Jupiter name, though
`Jovrix` is the closer IRIX-shaped option:

```
$ uname -a
Jovis 1.0 indy MIPS-III
$ echo $HOSTNAME
indy
```

`jovis$` is a good prompt. `jovis-libc`, `jovis-kernel`, `jovis-sdk` are good
package names. The adjective is `Jovian`; the community are `Jovians`.

**Legal.** The quick US screen found only two `JOVIS` marks, both dead:

- serial 75234862, class 9, "computer programs and user manuals", filed 1997,
  **cancelled 16 July 2005**;
- serial 75891439, class 33, wine, filed 2000, **abandoned 6 December 2003**.

No live US `JOVIS` mark in class 9 or 42 surfaced. There are unregistered users:
JOVIS Solutions (a US federal IT contractor), Jovis AI (an Indian project
management tool), Jovis Infotech (India), Jovis Techno Services (India), and
Jovis Verlag (a Berlin art/architecture publisher). They are small and in
adjacent fields, but they are the reason a formal clearance search is still
needed. The name is a Latin word, not an SGI mark, so it does not carry the IRIX
problem.

**Software.** The name is used by `snu-jovis`, a PostgreSQL query-optimisation
visualiser, and by a few small mobile/IM projects. **There is no Jovis
operating system.** npm, PyPI and crates.io all returned 404 for `jovis` on 25
October 2026.

**Namespaces.** `jovis.com`, `jovis.io`, `jovis.net`, `jovis.org` and `jovis.dev`
are all registered (some may be parked); `jovis.au` had no DNS record on 25
October 2026 and may be available subject to `.au` eligibility. The zero-cost
option is a subdomain of the existing site: **`jovis.jupiter.au`**. On GitHub,
`github.com/jovis` is taken, but **`github.com/jovis-os` was available**.

**Risks.** `Jove OS` is an existing hobby kernel, and `JOVIX` is a live software
mark. `Jovis` is distinct from both in spelling and sound, but they will appear
in the same search results. The name is also close enough to the JOVIS companies
that a formal clearance is required before filing. None of these is a blocker
for a GPL-3.0 project; they are reasons to do the search and to add a
non-affiliation notice.

**Verdict.** The best clean-break option: the most elegant Jupiter name, with a
clean US register and a good Unix sound. It is the right choice if the IRIX
resemblance matters less than the Jupiter identity. If you want the IRIX sound,
`Jovrix` is the pick.

### 2. Jovius — runner-up

**Meaning.** The adjective *Iovius* / `Jovius` means "of Jupiter" or "Jovian".
It was an imperial epithet (Diocletian was *Iovius*) and the Latin name of the
historian Paolo Giovio. It is one step more ornate than `Jovis`.

**Sound.** Three syllables, `-us` ending. `jovius$` looks like a Roman Unix;
`uname` reports `Jovius`. It is less crisp than `Jovis`, but it has more
presence on a title page.

**Legal.** The quick US screen found **no `JOVIUS` marks at all**. There are
companies (Jovius Technologies in India, Jovius Capital) and an npm package
(`jovius`, a tiny React configuration library, last published 2024), but no
operating system and no registered US mark. This is the cleanest legal screen
of the shortlist.

**Namespaces.** `jovius.net` and `jovius.io` were available (RDAP 404) on 25
October 2026; `jovius.com` is a domain landing page, and `jovius.org`/`.dev` are
registered. `github.com/jovius` is taken, but `github.com/jovius-os` was
available. npm has a package; PyPI and crates.io are free.

**Risks.** It is close to `JOVIS` and `JOVIAN` in sound and meaning, and the
`Jovian` storage/OS uses are the most likely source of confusion. It is also
less obviously a Unix name than `Jovis`.

**Verdict.** The fallback if `Jovis` clearance fails, or the choice if the
project wants a more distinctive, less common Latin form.

### 3. Tonans — the clean alternative

**Meaning.** *Tonans* is the participle "thundering"; **Jupiter Tonans** is
"Jupiter the Thunderer", a standard epithet and a famous statue type.

**Sound.** Two syllables, hard `t` and `n`, `-ans` ending. `tonans$` reads as a
1980s Unix; `uname` reports `Tonans`. It is short, strong and unlike anything
else in the OS space.

**Legal.** No US `TONANS` marks were found. `tonans.com` is listed for sale;
`tonans.dev`, `.io` and `.net` had no DNS on 25 October 2026. npm, PyPI and
crates.io are free. This is a very clean namespace.

**Risks.** It is obscure. Most people will not connect it to Jupiter without the
story, and it can be misheard as "tonal" or "tonnage". It is a better *release
codename* than a first name unless the user wants a name that requires a
one-line explanation.

**Verdict.** The best choice if the priority is a clean, SGI-shaped name with
maximum distance from the `Jov-` cluster.

### 4. Thebe — the moon option

**Meaning.** Thebe is a nymph loved by Zeus/Jupiter and a small inner moon of
Jupiter (Jupiter XIV), one of the ring moons. It is short, hard and classical.

**Sound.** Two syllables, `th` and `b`, `-e` ending. `thebe$` looks like a Unix;
`uname` reports `Thebe`. It is less obviously Jupiter than `Jovis`, but it is
more obviously SGI: it could sit next to `Onyx` and `Indy` without looking out
of place.

**Legal.** No US `THEBE` class 9/42 marks were found; the live US marks are
fashion (Thebe Magugu) and the dead ones are housewares. The software
collisions are **Jupyter's Thebe** (`thebe-core`, `sphinx-thebe`) and **Thebe
Space**, an Australian defence/space software company. Neither is an OS.

**Namespaces.** `thebe.com`, `.org`, `.net` and `.dev` are registered; `thebe.io`
was available on 25 October 2026. npm and PyPI have `thebe` packages; crates.io
is free. A GitHub `thebe-os` namespace is likely available.

**Risks.** The Jupyter association is strong in developer search results, and
the name does not say "Jupiter" to a general audience. It is a good name, but
not the best fit for *this* project's personal story.

**Verdict.** The best moon name if the user wants to avoid the `Jov-` cluster
without going as obscure as `Tonans`.

### 5. Fulmen — the SGI-shaped alternative

**Meaning.** *Fulmen* is the Latin thunderbolt, Jupiter's weapon. It is a
natural one-word SGI-style name (`Fuel`, `Onyx`, `Octane`).

**Sound.** Two syllables, hard `f` and `m`, `-en` ending. It sounds like a
firmware or a lighting brand more than a Unix, but it is strong and memorable.

**Legal.** The US screen shows two dead `FULMEN` marks (housewares, clothing),
one live `ELIA FULMEN` jewellery mark, and a **pending `FULMEN GAME STUDIOS`
class 42 mark** for video/computer game development. Fulmen is also a battery
brand (Exide) and an Australian lighting brand. No software OS mark, but the
pending class 42 mark is a caution.

**Verdict.** A strong style match, but the legal screen is weaker than `Jovis`,
`Jovius` or `Tonans`. Keep it as a codename or a fallback, not the first choice.

## The naming system

A name is more than a word; it is a system. The same system works for `Jovrix`
(Track A) and `Jovis` (Track C); substitute the name.

| Element | Track A — Jovrix | Track C — Jovis |
|---|---|---|
| OS name | **Jovrix** | **Jovis** |
| Machine | **Indy** | **Indy** |
| Tagline | **Jovrix — Jupiter's IRIX for the Indy.** | **Jovis — of Jupiter. A Unix for the Indy.** |
| Pronunciation | **JOV-riks** | **JOH-vis** |
| Prompt | `jovrix$` | `jovis$` |
| Package prefix | `jovrix-` | `jovis-` |
| Release codenames | **Jupiter's moons** | **Jupiter's moons** |
| Mascot | **Aquila**, the eagle, with a thunderbolt | same |
| Palette | Indy electric blue + Jupiter amber/cream/ochre | same |
| Documentation | **The Jovrix Handbook** | **The Jovis Handbook** |
| Version | **1.0**, not 7 | **1.0**, not 7 |

The `-rix` in `Jovrix` is a deliberate echo of IRIX, and the `Jov-` is Jupiter.
The name says both things at once: *Jupiter's IRIX*. That is the closest a new
mark can come to the old identity without using it. Track B (`Indrix`) uses the
same system with `indrix$` and `indrix-`. Track E (`Septimix`) uses `septimix$`
and `septimix-`, with the tagline *Septimix — the seventh Unix for the Indy*.

The release names are a ready-made roadmap. Io is the volcanic, active first
release (bring-up); Europa is the ocean world (the POSIX/userland release);
Ganymede is the largest moon (the full desktop); Callisto is the ancient,
cratered moon (long-term support). None of them is a software trademark in the
OS field, and they are all in the Jupiter system.

The visual identity should not clone the SGI logo or the Indy badge. Use the
*idea* of the Indy: the electric-blue pizza box, the bold colour, the 1990s
technical confidence. Pair it with Jupiter's amber and cream, an eagle or a
thunderbolt, and a wordmark in a clean geometric sans. The project is a
successor in spirit, not a counterfeit.

## If adopted: migration plan

This is a sketch, not a committed plan. The examples use `Jovrix`; substitute
`Indrix` or `Jovis` if that is the chosen track. The important thing is to decide
the name before the module SDK and public ABI freeze.

### Phase 0 — clearance and namespace

1. Commission a formal trademark search in Australia (IP Australia), the US
   (USPTO) and the EU (EUIPO) for the chosen name in classes 9 and 42. For
   `Jovrix`, pay particular attention to the live `JOVIX` class 9 mark; for
   `Indrix`, to the existing `INDRIX` software and the `IRIX` marks; for `Jovis`,
   to the JOVIS companies.
2. If clear, file an Australian application in classes 9 and 42; consider a US
   intent-to-use application if the project will be distributed there.
3. Secure `jovrix.au` (if eligible) or use `jovrix.jupiter.au`; secure
   `github.com/jovrix-os`; reserve `jovrix` on npm, PyPI and crates.io even if the
   packages are placeholders.
4. Add a non-affiliation notice: "Jovrix is an independent clean-room project. It
   is not affiliated with Silicon Graphics, SGI, or Hewlett Packard Enterprise.
   IRIX is a trademark of its respective owner."

### Phase 1 — user-facing rename

- README title, tagline, badges and links.
- `docs/README.md`, `docs/SUMMARY.md`, the book, and the research index.
- Boot banner, `uname`, MCP `status`, console strings and release artefacts.
- GitHub Pages URL and the boot config URL
  (`https://raw.githubusercontent.com/irix7/os/main/boot/config.conf`).
- Module SDK documentation and the `v0.3.0` tag notes.
- Package metadata and `THIRD-PARTY-NOTICES.md`.

Keep internal crate names for now. The `irix-elf` crate is about the ELF format,
not the brand; it can stay. The `irix7-libc` shim is OS-specific and should become
`jovrix-libc` at the next major version. `irix7c` can stay until the toolchain
rename, because it targets the IRIX ABI rather than the OS brand.

### Phase 2 — repository and organisation

Rename `irix7/os` to `jovrix-os/os` and `irix7/os-sdk` to `jovrix-os/os-sdk`.
GitHub redirects old URLs, but the Pages site and the raw boot-config URL change.
Update the release workflow to publish the new URLs and digests. The module ABI
tag `v0.3.0` and the service-table layout do not change; only the repository and
package names do.

### Phase 3 — crates and ABI surface

Rename the OS-specific crates (`irix7-libc` → `jovrix-libc`) and the user-facing
binary names. Keep compatibility aliases for one release if external modules
link the old names. The ABI itself stays: a module built against `v0.3.0` should
still run if the service table is unchanged.

### Phase 4 — version and story

Reset to **Jovrix 1.0**. The compatibility target remains IRIX 6.5; the marketing
line is "the successor SGI might have built", not "IRIX 7". The roadmap's v1.0
canopy already fits this reset.

## What not to do

- **Do not call it `<Name> 7`.** The "7" was an IRIX version claim; a new name
  should start at 1.0. The compatibility story can still say "the IRIX 6.5
  successor".
- **Do not use `<Name>OS` as the primary name.** `Jovrix`, `Indrix` or `Jovis`
  is stronger and more Unix-like. `Jovrix OS` is fine as a descriptive phrase.
- **Do not use `Iryx`.** `IRYX OS` is a live/pending class 9 mark for an
  operating system. The obvious IRIX-with-a-Y is already taken.
- **Do not use `Irixum`, `Irixus` or `Irixis` without clearance.** They are the
  closest to the literal string, which is exactly why they are the most likely
  to be refused for similarity to `IRIX`.
- **Do not use an SGI product name.** `Indy`, `Indigo`, `Iris`, `Onyx`, `Octane`,
  `Origin`, `Fuel`, `Tezro`, `Altix` and `Virtu` all recreate the IRIX problem.
- **Do not drop the IRIX compatibility statement.** "Runs IRIX 6.5 binaries" is
  the project's most important technical claim; it is nominative fair use and
  should stay.
- **Do not rely on this report as legal advice.** The trademark screen is a
  preliminary US federal search, not a clearance.
